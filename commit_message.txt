feat: Event-driven camera recording system with countdown, beeping, and status notifications

Implement comprehensive camera recording solution for axinCam with the following features:

CONFIGURATION MANAGEMENT
- Created CamRecorder singleton (Services/CamRecorder.cs) centralizing all recording settings:
  * PreRecordTimeS: Pre-recording countdown duration (default 10s)
  * RecordTimeS: Recording duration (default 30s)
  * BeepRepeatTimeMs: Interval for countdown beeps (0 to disable)
  * Orientation enum: Portrait/Landscape
  * Face enum: Front/Back camera selection
  * VideoFileMap: Custom video file paths
  * Camera properties: FPS, resolution, bitrate, etc.

EVENT SYSTEM
- Implemented custom EventArgs classes (Services/RecordingEventArgs.cs):
  * CountdownProgressEventArgs: Reports remaining seconds every BeepRepeatTimeMs
  * RecordingStartedEventArgs: Fired when recording begins with duration
  * RecordingCompletedEventArgs: Reports success/failure and video file path
- Added delegate types: CountdownProgressEventHandler, RecordingStartedEventHandler, RecordingCompletedEventHandler

PUBLIC API (CameraViewHandler)
- StartRecordingSequence(): Async method managing entire recording workflow from countdown to save
- CancelRecordingSequence(): Cancels countdown or stops recording early (saves file)
- StopCountdownBeeping(): Silences countdown beeps
- GetLastRecordedVideoPath(): Returns path to most recently recorded video
- PlayBeep(), StartRecording(), StopRecording(): Low-level recording controls

AUDIO FEEDBACK
- Fixed tone blending issue: Multiplied beep delays by iteration index for sequential playback
- Countdown beeping: Plays every BeepRepeatTimeMs until 3 seconds before recording
- Pre-recording double beep (100ms): Signals imminent start
- Recording long beep (300ms): Marks recording beginning
- Stop triple beep (100ms x3): Confirms recording completion
- Beeping fully disableable: Set BeepRepeatTimeMs=0 to silence all audio

RECORDING WORKFLOW
1. User clicks Start → Countdown begins with beeping
2. StatusLabel updates every 500ms: "Starting in X sec"
3. At preRecordTimeS - 3 sec: Beeping stops, double beep plays
4. At preRecordTimeS - 2 sec: Recording starts, long beep plays
5. Recording continues for RecordTimeS seconds
6. User can stop early during countdown (cancels) or recording (saves shortened file)
7. On completion: Triple beep, StatusLabel shows "Ready", buttons reset
8. RecordingCompleted event fires with Success=true and video file path

STATE MANAGEMENT
- Added _isRecording flag to distinguish between countdown cancellation and early stop
- Countdown cancellation: Sends error notification (Success=false)
- Early stop: Saves shortened footage (Success=true)
- CancellationTokenSource ensures clean cancellation flow

EXTERNAL APP INTEGRATION
- recordCam library can be embedded in any MAUI app
- External apps instantiate CameraView and obtain CameraViewHandler
- Subscribe to events for UI updates and file notifications
- Call StartRecordingSequence() from any button (not just embedded UI)
- Access recorded video path via GetLastRecordedVideoPath()

LOGGING
- Comprehensive debug logging throughout:
  * Handler initialization and event subscription
  * Countdown progress and beeping
  * Recording state changes
  * Event firing with subscriber count
  * Button state transitions
  * Enables easy debugging of recording issues
